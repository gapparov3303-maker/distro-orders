# Оптовый каталог: Telegram-бот для дистрибьюторской компании

Мини-приложение внутри Telegram-бота. Клиент открывает каталог продуктов питания, выбирает товары по категориям, указывает количество (до 500 штук одного товара), выбирает **самовывоз или доставку по адресу** и оформляет заказ. Продавцу заказ приходит в Telegram карточкой с составом, адресом и кнопками «Принять», «Готов», «Выдан/Доставлен». Клиенту бот сам пишет, когда статус меняется. Оплата только при получении. Два языка: русский и узбекский (латиница).

Это отдельный проект: свой бот, свой Cloudflare Worker `distro-orders`, своя база. Он никак не связан с ботом VIVA Cakes и ничего в нём не меняет. Конструктора тортов здесь нет, только каталог.

Всё работает на Cloudflare Workers, бесплатного тарифа хватает с большим запасом. Своего сервера не нужно.

## Что понадобится

- Новый бот в Telegram: создаётся у @BotFather за минуту (шаг 1).
- Аккаунт на github.com (уже есть) и аккаунт Cloudflare (уже есть).
- Компьютер не нужен, всё делается в браузере. Токен бота и код продавца вы вводите **только сами** на сайте Cloudflare и никому их не присылаете, в том числе мне.

## Запуск нового бота (около 20 минут, без терминала)

**1. Создайте бота**

В Telegram откройте @BotFather → `/newbot`. Придумайте название (например, «Навои Трейд») и имя пользователя (латиницей, обязательно заканчивается на `bot`, например `navoi_trade_bot`). BotFather пришлёт **токен** (длинная строка с двоеточием). Пока оставьте его в чате BotFather, он понадобится на шаге 4.

**2. Загрузите файлы на GitHub**

1. На github.com нажмите «+» → New repository. Имя: `distro-orders`. Нажмите Create repository.
2. На пустой странице нажмите ссылку **uploading an existing file**.
3. Распакуйте архив `distro-bot.zip`. Откройте распакованную папку и перетащите в окно браузера **всё её содержимое** (файлы `README.md`, `build.js`, `package.json`, `wrangler.toml` и папки `src`, `dist`, `test`), а не саму папку `distro-bot`. Файл `wrangler.toml` должен лежать в корне репозитория.
4. Дождитесь, пока все файлы загрузятся, и нажмите зелёную кнопку Commit changes.

**3. Подключите репозиторий к Cloudflare**

1. На dash.cloudflare.com откройте Workers & Pages → Create application → Import a repository (или «Connect to Git»).
2. Выберите GitHub-репозиторий `distro-orders`.
3. Имя проекта оставьте `distro-orders`: оно должно совпадать с `name` в `wrangler.toml`.
4. Build command: `npm run build`. Deploy command: `npx wrangler deploy`. Нажмите Save and Deploy.
5. Через 2–3 минуты сборка завершится. Адрес приложения будет вида `https://distro-orders.gapparov3303.workers.dev`.

**4. Введите токен и код продавца (секреты)**

Откройте новый проект `distro-orders` → Settings → Variables and Secrets → Add. Добавьте два значения типа **Secret**:

- `BOT_TOKEN`: токен из BotFather;
- `ADMIN_CODE`: ваш пароль продавца. Длинная фраза или набор символов от 12 знаков, которую вы больше нигде не используете. Запомните её.

Нажмите Deploy (Save and deploy). Секреты вступят в силу после этого.

**5. Свяжите бота с сервером**

Откройте в браузере `https://distro-orders.gapparov3303.workers.dev/setup`, введите `ADMIN_CODE` и нажмите «Подключить бота». Все строки отчёта должны быть зелёными (✔): токен, приём сообщений, кнопка меню «🛒 Каталог», команды.

**6. Станьте продавцом**

В Telegram откройте своего нового бота и отправьте:

```
/admin ВАШ_КОД
```

Бот подтвердит и сразу удалит сообщение с кодом из переписки. С этого момента заказы приходят вам. Если продавцов несколько, каждый отправляет эту команду со своего аккаунта.

**7. Наполните каталог**

Откройте бота → кнопка меню «🛒 Каталог» (слева от поля ввода) → вкладка «Продавец»:

1. «Настройки»: название компании, телефон, Telegram для вопросов, адрес самовывоза (по-русски и по-узбекски), сроки подготовки и часы работы. Если доставки нет, снимите галочку «Доставка по адресу включена».
2. «Каталог»: сначала категории («Масла», «Крупы»…), затем товары.

**8. Проверьте**

Со второго аккаунта (как настоящий клиент) откройте бота, добавьте товар в корзину, оформите заказ с самовывозом и ещё один с доставкой. В чат продавца придут карточки. Нажмите «Принять в работу», у клиента появится сообщение.

Необязательно: в @BotFather → ваш бот → Bot Settings → Configure Mini App (пункт может называться чуть иначе) можно указать тот же адрес, чтобы у бота появилась кнопка «Открыть» и ссылка для рассылки.

## Как пользоваться

**Продавец:**
- Новые заказы приходят в чат с ботом: состав с количеством и суммой, способ получения (самовывоз или доставка с адресом), дата и время, имя и телефон клиента, комментарий. Кнопки под заказом: «Принять в работу» → «Готов к выдаче» (самовывоз) или «Готов к отправке» (доставка) → «Выдан клиенту» или «Доставлен клиенту». Отмена просит подтверждение. Клиент получает сообщение при каждой смене статуса.
- В приложении (кнопка «🛒 Каталог» → вкладка «Продавец»):
  - «Заказы»: все заказы со статусами, счётчики «Новые», «В работе», «На сегодня», сумма завершённых; фильтры «Активные», «Завершены», «Отменены», «Все»; кнопка «Копировать» рядом с телефоном клиента;
  - «Каталог»: категории и товары;
  - «Настройки»: название, контакты, адрес самовывоза, доставка вкл/выкл, за сколько часов нужно заказывать самовывоз (по умолчанию 2) и доставку (по умолчанию 24), часы работы.
- Изменения видны клиентам сразу. Если клиент уже выбрал товар по старой цене, при оформлении он увидит «Продавец обновил цены» и подтвердит новую сумму.

**Каталог (продавец):**
1. Вкладка «Каталог». Создайте категории: «+ Добавить категорию», название по-русски и по-узбекски. Удалить можно только пустую категорию.
2. «+ Добавить товар»: название (рус. и узб.), описание (по желанию), категория, вес или объём одной единицы (г, кг, шт, мл, л) и цена за единицу в сумах. Цена за единицу: если мешок риса 25 кг стоит 410 000 сум, то вес 25, единица кг, цена 410000.
3. Фото: «Загрузить фото» → снимок из галереи или с камеры. Приложение само уменьшит его до 800 пикселей и сожмёт, обычные фото с телефона подходят. «Заменить фото» и «Убрать фото» работают так же.
4. Галочка «В наличии»: если снять, товар остаётся в каталоге серым и в корзину не добавляется.
5. Стрелки ▲ ▼ меняют порядок, «Удалить товар» просит подтверждение. Всё сохраняется само («Сохранено, клиенты видят изменения»).

**Клиент:**
- Открывает бота, нажимает «🛒 Каталог». Сверху название компании, поиск (появляется, когда товаров больше 8), категории. Карточка: фото, название, вес, цена, описание (нажмите, чтобы развернуть).
- «В корзину», затем кнопки «−» и «+» или ввод числа с клавиатуры (от 1 до 500 штук одного товара, до 30 разных товаров в заказе). Внизу всегда видна сумма и кнопка «Оформить заказ».
- В корзине: способ получения «Самовывоз» или «Доставка». Для доставки появляется поле адреса. Дальше имя или название компании, телефон, дата и время (шаг 30 минут, в часы работы, не раньше нужного запаса: для доставки он обычно больше), пожелания. Имя, телефон, способ и адрес запоминаются на телефоне для следующего заказа.
- «Заказы»: все заказы со статусом. Пока заказ «Новый», его можно отменить самому.
- Корзина хранится на телефоне, пока заказ не оформлен. Если продавец убрал или отключил товар, из корзины он пропадёт, а клиент увидит предупреждение.

## Безопасность

- Цены, названия и состав заказа сервер берёт сам из каталога. Подмена суммы или цен в телефоне клиента ничего не даёт. Количество (1–500, целое число), адрес, время и телефон проверяются на сервере.
- Вход клиентов подтверждается подписью Telegram, права продавца даёт только код `ADMIN_CODE`. После 8 неверных попыток код блокируется на час.
- От одного человека не принимается больше 5 неподтверждённых заказов; на весь склад не больше 300 активных заказов.
- Если токен бота когда-либо попал не туда: в BotFather `/revoke`, затем снова шаги 4 и 5.
- Приложение хранит имена, телефоны, адреса и Telegram-идентификаторы клиентов, как любой заказ. Резервной копии и выгрузки в таблицу нет: данные лежат в хранилище Cloudflare. Если понадобится выгрузка, это можно добавить.

## Если что-то не работает

- **Страница `/setup` показывает красное:** прочитайте текст рядом. Чаще всего неверный токен (проверьте секрет `BOT_TOKEN`, нажмите Deploy и откройте `/setup` снова).
- **Бот молчит на `/start`:** повторите шаг 5.
- **Приложение открывается, но заказ не отправляется:** откройте его именно из бота. В обычном браузере можно только смотреть.
- **Заказ на доставку не оформляется, пишет «Доставка сейчас недоступна»:** продавец выключил доставку в настройках, выберите самовывоз.
- **Сборка в Cloudflare красная:** проверьте, что `wrangler.toml` лежит в корне репозитория, а не в подпапке, и что имя проекта `distro-orders`.

## Обновление

Чтобы обновить бота, загрузите на GitHub новые файлы тем же способом (Add file → Upload files → Commit changes). Cloudflare пересоберёт приложение за 2–3 минуты. Данные (каталог, фото, заказы) при этом сохраняются.

## Для разработчика

- `src/shared.js` общий код приложения и сервера: настройки, единицы, статусы (у самовывоза и доставки свои названия), время и сетка слотов, текст заказа.
- `src/app.html` само приложение (интерфейс).
- `src/worker-src.js` сервер: Worker + Durable Object `Shop` (SQLite), webhook бота, `/setup`.
- `build.js` склеивает всё в `dist/worker.js` (`npm run build`); `npm run deploy` делает сборку и публикацию через `wrangler`, если у вас есть Node.js.
- `npm test` запускает 40 проверок сервера без интернета (поддельные Telegram и хранилище): вход и подпись, заказы с самовывозом и доставкой, количество 1–500, сроки, статусы, уведомления, каталог, фото, ограничения, длинные заказы.
- Хранилище (ключи Durable Object): `cfg` (настройки), `prod` (категории и товары: до 40 категорий и 300 товаров), `p:<id>` (фото товара: JPEG до 300 КБ), `o:<id>` (заказ), `m:<uid>` (заказы клиента), `act` и `hist` (активные и завершённые), `stats`, `admins`, `fail`.
- Заказ: `POST /api/order` с телом `{cart:[{id,qty}], form:{name,phone,mode,address,date,time,comment}, lang, expectTotal}`. `mode` равен `pickup` или `delivery`. Сервер сверяет цены с каталогом: расхождение суммы даёт `409 price_changed`, пропавший или отключённый товар даёт `409 unavailable`, выключенная доставка даёт `409 no_delivery`; во всех трёх случаях в ответе свежие `cfg` и `prod`. Заказ хранит копию позиций (название, вес, цена на момент заказа), поэтому смена каталога старые заказы не меняет. Номера заказов начинаются с `Z-`.
- Срок подготовки берётся из `shop.leadHours` (самовывоз) или `shop.deliveryLeadHours` (доставка); сервер даёт час запаса, чтобы не спорить с часами телефона.
- Фото товара загружается сырыми байтами (`PUT /api/admin/photo/<id>`), а не base64, чтобы сервер не тратил процессорное время на бесплатном тарифе. Сервер проверяет заголовок JPEG и размеры. Публичный адрес `/img/<id>?v=<версия>` с долгим кэшем браузера; версию выставляет сервер при каждой загрузке.
- Длинный заказ (до 30 строк по 500 штук с длинными названиями) не помещается в сообщение Telegram (лимит 4096 знаков): карточка продавца показывает первые позиции и строку «… и ещё N поз. (полный список в приложении)», итог и кнопки остаются.
